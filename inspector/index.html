mini-redis inspector

연결 확인 중

redis-cli 처럼 공백으로 인자를 나눈다. 공백이 든 값은 "따옴표"로. ↑ ↓ 로 이전 명령.

만료
조건

입력한 그대로 TCP 로 보낸다. \r \n \t \\ \xHH 는 바이트로 바꾼다. 연결은 이어진 채라서 반쪽만 보내고 나머지를 나중에 보낼 수 있다.

① 점진적 rehash 를 한 칸씩 보기

능동 rehash 를 끄고, 비운 뒤 키 5개를 넣는다. 키가 4개(버킷 4개)를 채운 다음 5번째에서 ht[1](버킷 8개)이 생긴다. 그다음 아무 명령이나 보내면 한 칸씩 옮겨진다.

② 만료: lazy 와 active

3초짜리 키를 만든다. 표의 TTL 이 0 을 지나면 '만료됨'으로 바뀌고, 100ms 마다 도는 active 만료가 곧 지운다. 능동 rehash 와 상관없이 만료는 계속 돈다.

③ 키 많이 넣기

별도 연결로 SET 을 파이프라이닝해서 넣는다(로그에는 요약만). 버킷 수가 2배씩 커지는 것과 체인 길이를 본다.

개 ms TTL(0=없음)

주고받은 바이트 최근 것이 위

*3 $3 머리줄 SET 내용 PING inline $5 hel 아직 덜 옴 \r\n 줄 끝
아직 보낸 명령이 없다. 위에서 명령을 보내 보자.

키 공간

저장된 키 main 과 expires 를 합쳐서. DEBUG HT 로 읽어 rehash 도 lazy 만료도 일으키지 않는다
